# MULTI Research Group Website - Development Context

## Project Overview

Single-page website for the MULTI research group at SCI Institute, University of Utah. Displays group introduction, team member carousel, and filterable publication list.

## Core Principle: Data-Interface Separation

All content lives in data files (`data/`). Maintainers update content without touching code.

- `data/group.json` - Group description
- `data/team.json` - Team members with `authorVariants` for publication matching
- `data/publications.bib` - Publications in BibTeX format (parsed client-side). **Generated, never hand-edited:** see Publication Sync below

## Technology Constraints

**Allowed:**
- HTML5, CSS3, jQuery 3.7+ (CDN)
- JSON for structured data, BibTeX for publications
- Google Fonts (Montserrat, Source Sans Pro)

**Not Allowed:**
- JavaScript frameworks (React, Vue, Angular)
- CSS preprocessors (Sass, Less)
- Build tools (Webpack, Vite, npm)
- Server-side code

The one exception is `scripts/sync_publications.py` (Python standard library only), a maintenance job run by a GitHub Action. It never ships to visitors.

## Publication Sync

SCI keeps publications in a database it will not change for us, exported daily to https://publications.sci.utah.edu/publications/sci.bib. `.github/workflows/sync-publications.yml` fetches it once a day with a conditional GET (a 304 with no body when unchanged; do not make this more frequent or unconditional) and rebuilds `data/publications.bib`:

- `data/source/sci.bib`, `data/source/fetch-state.json` - the export as fetched, and its ETag
- `data/publications-rules.json` - rule book: selection (C. R. Johnson as author or editor) and ordered cleanup rules, each with a reason
- `data/publications-overrides.json` - per-entry patch / exclude / add, each with a reason

Every change is committed directly to `main` with a generated message listing what changed and which rules and overrides applied, and why: the commit log is the decision log. Fix data problems with a rule (a pattern) or an override (one entry), never by editing the generated file. Maintainer steps are in `docs/CONTENT-UPDATE.md`.

## File Structure

```
index.html              # Single page
css/variables.css       # CSS custom properties (colors, fonts, spacing)
css/multi.css           # All styles
js/multi.js             # All JavaScript (includes BibTeX parser)
data/group.json         # Group info
data/team.json          # Team members
data/publications.bib   # Publications (BibTeX format), generated by scripts/sync_publications.py
data/publications-rules.json, data/publications-overrides.json, data/source/   # inputs to the sync
scripts/sync_publications.py                  # daily publication sync (.github/workflows/)
images/team/            # Member photos (400x400 JPEG)
images/logos/           # University and SCI logos
docs/                   # Documentation
```

## Code Style

**CSS:**
- BEM naming: `.block__element--modifier`
- Use CSS variables from `variables.css`
- Mobile-first with `min-width` media queries

**JavaScript:**
- camelCase for variables/functions
- UPPER_SNAKE_CASE for constants
- `$` prefix for jQuery elements
- Module pattern (single `MULTI` object)

## Key Features

1. **Team Carousel:** Horizontal scrolling cards, clickable to filter publications
2. **Publication Filtering:** Matches `authorVariants` from team.json against publication authors
3. **Search:** Debounced (300ms), searches title/authors/venue

## Brand Requirements

- Primary color: Utah Red `#BE0000`
- Hover: Red Rocks `#890000`
- Background: Salt Flat Grey `#E2E6E6`
- Headings: Montserrat Bold
- Body: Source Sans Pro
